## 二、确认的问题清单

### 🔴 HIGH（10 项，全部经源码实证）

**H1. guard 受击响应存在"排队 drain 先于拦截"竞态 → 战斗可能永不执行**
`src/core/fl-guard.js:63-66` + `src/tasks/manager.js:263-282,496-507`。
`preemptForCombat` 循环停 running exclusive 任务时，`stopTask` 内部立即 `_drainExclusive()` 把**排队中的** exclusive 任务先启动；随后遍历的队列已排空。若 guard combat 启动时撞上该任务 → `startTask` 返回 null → fl-guard 跳过 await → finally 直接移除 combat 任务 → **bot 对攻击者零响应**（v1.5.1 新功能核心路径）。
→ 修复：抢占路径先全停（含 `[...this._pendingExclusive]` 快照）再统一 drain；或给 `stopTask` 加 `drain:false` 选项。补排队抢占回归测试。

**H2. `place` 原语在真实服务器 100% 失败**
`src/core/primitives/build.js:86` + mineflayer `generic_place.js:107`。
`placeBlock(refBlock, face)` 的 face 传字符串 `'up'`，mineflayer 的 `vectorToDirection` 读 `v.y/v.z/v.x`（undefined 比较全 false）→ `assert.ok(false)` **抛 AssertionError**。本地补丁未触及 generic_place.js（已核对补丁清单）。测试用桩函数掩盖真实签名（`tests/l2.test.mjs:893`），648 全绿也测不出来。
→ 修复：faceVector 是"参考块→目标"方向，恰为 `off` 的负向量：`c.bot.placeBlock(refBlock, new Vec3(-off[0], -off[1], -off[2]))`；补一条**不桩 placeBlock、只断言入参形状与方向**的测试。

**H3. fatal 停服 webhook 通知实际失效**
`src/index.js:44-58` + `src/core/connection.js:213-234`。
致命断线路径（duplicate_login/whitelist/version_mismatch）**从头到尾没有调用 notifier**；unhandledRejection 路径是 fire-and-forget 后立即 `exit(2)`，fetch 来不及完成。README/architecture 承诺的"fatal 停服推送（无人值守唯一感知通道）"不成立。
→ 修复：ConnectionManager 加 `onFatal` 钩子；fatalExit 中先 `await` 通知（3s 上限 race）再 flush+exit。

**H4. error 事件缺状态守卫 → 单次断线 reconnectCount 双计数**
`src/core/connection.js:176-180`。
`kicked → 计数+1 → RECONNECTING → socket 关闭 error → 再计数+1`。end 处理器有 `RECONNECTING/_fatalExit` 守卫而 error 没有。"累计重连 N 次"广播、`/metrics`、`reconnectCount >= 3` 告警全部失真（约 2 倍速触发）；fatal 判定后迟到的 error 在 exit 窗口内仍可能调度重连。
→ 修复：error 处理器补同款两行守卫 + 断线事件序列（kicked/error/end）计数正确性单测。

**H5. 命令反馈无 per-sender 限流 → 0 门槛刷屏踢服 DoS**
`src/commands/registry.js:56-77` + `src/core/fl-chat.js:25-28` + `src/core/chat.js:13-20,96-106`。
权限拒绝/未知命令/冷却提示/usage/错误五条反馈路径全部无速率限制；冷却只在 op 命令**通过 isOp 之后**才生效。任意玩家 10s 内发 6-7 条 `!` 消息 → bot 回 6-7 条 → Paper spam 检测踢掉 **bot**（chat.js 注释已实证 6 片 100ms 触发）→ 断线重连循环 + 任务中断，可反复触发。`!agent chat` 还叠加云端 LLM 额度消耗。
→ 修复：聊天入口 per-sender token bucket 覆盖**所有**回复路径（未知/拒绝/冷却/usage/错误统一纳入）；`!agent chat` 加每日配额开关（默认关闭以兼容现状）。

**H6. 命令发送者身份来自显示名正则提取 → 条件性提权**
`src/core/fl-chat.js:30` + mineflayer `chat.js:3-4,207`。
`bot.on('chat')` 走 `LEGACY_VANILLA_CHAT_REGEX` 对**渲染后文本**捕获用户名（分隔符前最后一个 `\w+`）。Paper + 昵称/前缀插件把显示名渲染进消息时，`<Sir Steve> hi` 提取出 `Steve`——若 ops 白名单含 `steve` 即通过 `isOp`，可执行 `!status/!reload/!say/!find/!agent act` 全部 op 命令。条件性（需显示名与用户名不同），但离线服白名单是唯一认证。同一弱点使 bot 自我回显过滤存在绕面。
→ 修复：改用 playerChat 包的权威身份（`data.sender` 实体 id → `bot.players` 精确匹配 username）。

**H7. L2 目标操作不读磁盘 → 重启后 `!agent goal set` 永久抹掉会话历史与摘要**
`src/l2/agent-interface.js:861-890`。
`setGoal` 用 `getSession() ?? {history:[],...}` 兜底（仅内存），磁盘回填只在 `chat()` 里有（545-557 行）。重启或 LRU 驱逐后首次 set goal → 空会话整体覆盖 `sessions.json` 条目 → 该玩家多轮上下文+滚动摘要不可恢复；`getGoal/clearGoal` 同样误报。确定性数据丢失。
→ 修复：提取 `loadSession()`（内存 miss → 磁盘回填 + putBounded），三个方法统一走它；补"重启后 setGoal 保留历史"测试。

**H8. `interact_entity` 无接近/距离判定 → breed 远距喂食假成功**
`src/core/primitives/interact.js:62-99` + `src/tasks/scripts/breed.js:54`。
全实体表重扫取最近后直接 `useEntityOn`——不接近、不查距离。服务端 reach 校验静默拒绝 >~4 格交互，但 `fed++` 与 5 分钟冷却表照记 → 实际零繁殖、`maxBreedings` 假完成；LLM 手动喂食同受影响。脚本化重写时把旧版 `_approach`（approachEntity）丢了。
→ 修复：interact_entity 加 approachEntity（range≤3，失败 fed:0）或距离上限过滤后再 useEntityOn。

**H9. executor 超时不中止 handler → 幽灵动作持续产生未审计副作用**
`src/core/executor.js:81` + 各原语时间预算。
executor 的 `withTimeout` 只拒绝等待、不 abort `runtime.signal`。时间预算倒挂：interact_entity（30s 超时 vs 最坏 300s）、collect_blocks（120s vs 480s）、harvest_animals（30s vs 150s）、sleep（305s vs 600s）。报"超时"后底层喂食/挖掘/移动继续跑，与下一动作争抢 pathfinder，且不落审计——M6 修复过的"幽灵动作"类问题在 executor 超时路径残留。
→ 修复：方案 A（推荐）runAction 内每次调用新建 AbortController，`withTimeout` 触发时同步 `signal.abort()` 下发给 handler（与外部 signal 合并）；方案 B 逐原语核对 timeoutMs ≥ 内部最坏时长。建议 A，一劳永逸。

**H10. combat 任务攻击目标与扫描口径不一致 → 可追出区域作战**
`src/tasks/scripts/combat.js:79,89` + `src/core/primitives/combat.js:45-52,70`。
任务脚本用 `observe_entities`（aggroRange + area）过滤出 `targets`，但 `attack` 原语**全实体表重扫**（无 maxDistance/area 参数），取全图最近敌对实体；`approachEntity` 的 isInterrupted 上限硬编码 64 格——与 aggroRange/area 无关。
→ 修复：`attack` 原语增加 `maxDistance/area`（或候选实体 id 列表）参数，目标选择与脚本扫描口径统一；64 格上限改为调用方传入（默认 64 保持 LLM 路径兼容）。

## 四、正向观察（值得保持）
