# L2 LLM 层（骨架）

## 当前状态

- `config/l2.enabled=false`（默认）：`createL2()` 返回 null，**零额外依赖**（`npm ls` 验证无新增包）
- 启用后 `!agent chat hi` 返回桩回复（骨架阶段）
- 契约（已冻结）：`AgentInterface { chat(user,text) → {reply}, act(name,params) → {ok,result}, stop() }`

## 接入 mindcraft 的方案（设计，未实现）

**不要**将 mindcraft 作为进程内依赖：它锁定 `mineflayer 4.33.0` + 6 个 patch-package 补丁，与本项目 pin 的 PR 分支冲突，且无测试保障。

采用 **AgentProcess 模式**（mindcraft 自身的设计）：

```
┌─ minecraft-bot (L1 进程) ──────────────┐      ┌─ agent 子进程 (mindcraft) ─┐
│ AgentInterface.act('mine-iron', {}) ──────> │  skills 执行（调用 L1 任务）   │
│ chat(user, text) ────────────────────────> │  LLM 对话/推理                │
│                                        <─────  JSONL: {"type":"result",...} │
└──────────────────────────────────────────┘      └───────────────────────────┘
```

通信协议（JSONL over stdin/stdout）：

```json
L1 → agent: {"type":"act","name":"mine-iron","params":{}}
L1 → agent: {"type":"chat","user":"steve","text":"hi"}
agent → L1: {"type":"result","ok":true,"result":{...}}
agent → L1: {"type":"event","event":"state","data":"..."}
```

- L1 暴露给 agent 的技能 = TaskManager 启停 + 命令系统（Voyager control_primitives 思想的落地）
- 代码骨架已预留：`src/l2/mindcraft-adapter.js`
- mindcraft 的可借鉴生产模式（本项目 L1 已实现等价物）：
  - LoginGuard 断线分类 → `src/core/reconnect.js`
  - 10s 崩溃保护 → `reconnect.minGapMs` + systemd `StartLimitBurst`
  - 配置分层 → `src/core/config.js`

## 启用 L2 才引入的依赖

不进 package.json，按需安装（docs 记录）：

```bash
# 按 provider 选择，例如：
npm i openai        # OpenAI/DeepSeek 兼容
npm i @anthropic-ai/sdk
# mindcraft agent 子进程自身的依赖由其独立 package.json 管理（子进程工作目录隔离）
```
