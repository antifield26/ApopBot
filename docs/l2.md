# L2 LLM 层（双 Provider，进程内）

## 当前状态（0.2.0 已实现）

- `l2.enabled=false`（默认）：`createL2()` 返回 null，**零额外依赖**（无 SDK、无网络）
- 启用后 `!agent chat <text>` 走完整 LLM 工具循环；`!agent act <name> [json]` 直调技能（op-only）
- **双 Provider**：`provider: auto`（默认，云端优先，失败自动回退本地 Ollama）| `cloud` | `ollama`
- 依赖：Node 22 全局 `fetch`，**即使启用也零新增 npm 依赖**

## 架构（与早期方案的差异）

早期设计借鉴 mindcraft 的 **AgentProcess 模式**（子进程 + JSONL IPC）。最终实现改为**进程内模块**：

- 单 bot、`maxSteps`（默认 5）有界、无共享可变状态——子进程 IPC 的隔离收益在此规模为零，反而引入协议与调试成本
- mindcraft 锁定 `mineflayer 4.33.0` + 6 个 patch-package 补丁，与本项目 pin 的 PR 分支冲突——**不引入 mindcraft 依赖**
- `src/l2/mindcraft-adapter.js` 骨架已删除（本文件保留其设计思想作为历史记录）

```
!agent chat "状态如何？"
  └→ AgentInterface.chat(user, text)
       ├→ cooldown/busy 门
       └→ 循环 ≤maxSteps:
            ├→ provider.chat(messages, { tools, system, signal })
            │     ├→ CloudProvider  (Anthropic Messages API, x-api-key 只从 env 读)
            │     └→ OllamaProvider (OpenAI 兼容 /v1/chat/completions)
            ├→ toolCalls? → skills.execute（权限 + JSONSchema 校验）→ 结果回填 → 继续
            └→ 无工具调用 → 回复（≤250 字符）
```

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `l2.enabled` | `false` | 开关 |
| `l2.provider` | `auto` | `auto`=云端优先回退 Ollama；`cloud`/`ollama` 固定 |
| `l2.model` | `claude-sonnet-5` | 云端模型（baseURL 可配则兼容 OpenAI/Anthropic 端点） |
| `l2.cloudBaseUrl` | `https://api.anthropic.com/v1/messages` | 云端端点 |
| `l2.cloudApiKeyEnv` | `ANTHROPIC_API_KEY` | **API key 只从该环境变量读取**，绝不进配置文件、绝不写日志 |
| `l2.ollamaUrl` / `l2.ollamaModel` | `http://127.0.0.1:11434` / `qwen3.5:4b` | 本地 Ollama（需 `ollama pull qwen3.5:4b`；低配 PC 同机运行推荐 4B 量化档） |
| `l2.maxSteps` | `5` | 单次对话最多工具轮数（防失控循环） |
| `l2.cooldownMs` | `5000` | 请求冷却（防刷） |

启用示例（deploy.ps1 从 `config/service.env` 注入 NSSM 服务环境变量）：

```ini
# config/service.env（gitignore；KEY=VALUE 行，# 开头为注释）
MCBOT_L2_ENABLED=true
ANTHROPIC_API_KEY=sk-ant-...        # 只进环境变量，绝不进配置文件
```

## 技能（skills）

技能 = L1 能力的安全封装。`permission: op` 的技能只有 `config.ops` 白名单玩家可用；参数做极简 JSONSchema 校验。

| 技能 | 权限 | 说明 |
|---|---|---|
| `reply` | all | 以 Bot 身份聊天（≤250 字符自动分片） |
| `status` | all | 连接状态/坐标/血量/内存/重连次数 |
| `task_status` | all | 全部任务状态与计数 |
| `inventory_summary` | all | 背包物品聚合 |
| `list_skills` | all | 技能列表 |
| `move_to {x,y,z}` | op | 寻路移动 |
| `run_task {type,id,options}` | op | 运行时创建任务（7 种类型） |
| `stop_task {id}` | op | 停止并移除任务 |
| `follow_player {name\|off}` | op | 跟随/停止跟随 |

`!agent act status {}` 示例：`§astatus: {"state":"connected","reconnectCount":2,...}`

## 安全边界

- **密钥**：只从环境变量读取；fetch 失败日志不携带 key/body
- **工具滥用**：op 权限门 + maxSteps 上限 + cooldown + 参数校验；`run_task` 创建的任务同样受任务系统的区域/时长边界约束
- **回复长度**：≤250 字符，经 `sendChat` 分片
- **降级**：`auto` 模式下云端 4xx/网络错误自动回退 Ollama（一次）；Ollama 不可达时回复明确错误

## 历史记录：AgentProcess/JSONL IPC 方案（弃用）

早期设计（mindcraft 模式）：L1 主进程 ↔ agent 子进程 JSONL over stdin/stdout，协议 `{"type":"act"|"chat"|"result"|"event"}`。
弃用原因：单 bot 规模下 IPC 隔离无收益，进程内实现更简单可测；保留此段供未来多 bot/多 agent 场景参考。
