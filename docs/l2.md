# L2 LLM 层（双 Provider，进程内）

## 当前状态（0.2.0 已实现）

- `l2.enabled=false`（默认）：`createL2()` 返回 null，**零额外依赖**（无 SDK、无网络）
- 启用后 `!agent chat <text>` 走完整 LLM 工具循环；`!agent act <name> [json]` 直调技能（op-only）
- **双 Provider**：`provider: auto`（默认，云端优先，失败自动回退本地 Ollama）| `cloud` | `ollama`
- 依赖：Node 22 全局 `fetch`，**即使启用也零新增 npm 依赖**

## 架构（与早期方案的差异）

早期设计借鉴 mindcraft 的 **AgentProcess 模式**（子进程 + JSONL IPC）。最终实现改为**进程内模块**：

- 单 bot、`maxSteps`（默认 5）有界、无共享可变状态——子进程 IPC 的隔离收益在此规模为零，反而引入协议与调试成本
- mindcraft 锁定 `mineflayer 4.33.0` + 6 个 patch-package 补丁，与本项目 pin 的 PR 分支冲突——**不引入 mindcraft 依赖**
- `src/l2/mindcraft-adapter.js` 骨架已删除（本文件保留其设计思想作为历史记录）

```
!agent chat "状态如何？"
  └→ AgentInterface.chat(user, text)
       ├→ cooldown/busy 门
       └→ 循环 ≤maxSteps:
            ├→ provider.chat(messages, { tools, system, signal })
            │     ├→ CloudProvider  (Anthropic Messages API, x-api-key 只从 env 读)
            │     └→ OllamaProvider (OpenAI 兼容 /v1/chat/completions)
            ├→ toolCalls? → skills.execute（权限 + JSONSchema 校验）→ 结果回填 → 继续
            └→ 无工具调用 → 回复（≤250 字符）
```

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `l2.enabled` | `false` | 开关 |
| `l2.provider` | `auto` | `auto`=云端优先回退 Ollama；`cloud`/`ollama` 固定 |
| `l2.model` | `claude-sonnet-5` | 云端模型（baseURL 可配则兼容 OpenAI/Anthropic 端点） |
| `l2.cloudBaseUrl` | `https://api.anthropic.com/v1/messages` | 云端端点 |
| `l2.cloudApiKeyEnv` | `ANTHROPIC_API_KEY` | **API key 只从该环境变量读取**，绝不进配置文件、绝不写日志 |
| `l2.ollamaUrl` / `l2.ollamaModel` | `http://127.0.0.1:11434` / `qwen3.5:4b` | 本地 Ollama（需 `ollama pull qwen3.5:4b`；低配 PC 同机运行推荐 4B 量化档） |
| `l2.maxSteps` | `5` | 单次对话最多工具轮数（防失控循环） |
| `l2.cooldownMs` | `5000` | 请求冷却（防刷） |
| `l2.cloudTimeoutMs` / `l2.ollamaTimeoutMs` | `60000` | 单次生成超时（低配 Ollama 约 10-30 tok/s，长回复需放宽） |
| `l2.maxTokens` | `1024` | 单次生成最大 token 数 |
| `l2.ollamaNumCtx` | `4096` | Ollama 上下文窗口（native `/api/chat` 的 `options.num_ctx`——compat 端点不支持，官方 wont-fix）。8GB 机 4096 KV≈+1.5GB 贴近红线，可降 2048；预算裁剪保证任何窗口下输入 fit |
| `l2.envInjection` | `true` | 环境感知自动注入：每次对话 system 尾部追加 ≤150 字符环境行（坐标/昼夜/天气/维度/朝向/附近玩家 Top3） |

启用示例（deploy.ps1 从 `config/service.env` 注入 NSSM 服务环境变量）：

```ini
# config/service.env（gitignore；KEY=VALUE 行，# 开头为注释）
MCBOT_L2_ENABLED=true
ANTHROPIC_API_KEY=sk-ant-...        # 只进环境变量，绝不进配置文件
```

## 技能（skills）

技能 = L1 能力的安全封装。`permission: op` 的技能只有 `config.ops` 白名单玩家可用；参数做极简 JSONSchema 校验。

| 技能 | 权限 | 说明 |
|---|---|---|
| `reply` | all | 以 Bot 身份聊天（≤250 字符自动分片） |
| `status` | all | 连接状态/坐标/血量/内存/重连次数 |
| `task_status` | all | 全部任务状态与计数 |
| `inventory_summary` | all | 背包物品聚合 |
| `list_skills` | all | 技能列表 |
| `environment` | all | 环境快照：时间/昼夜/天气/维度/生物群系/朝向/附近玩家与实体（26.1 数据源：bot.time/bot.isRaining/bot.game.dimension/blockAt().biome） |
| `nearby_entities {filter,maxDistance}` | all | 附近实体列表（名/kind/距离/坐标，距离升序，可过滤 hostile 等） |
| `query_map {blockName,maxCount}` | all | 查询探索记忆中已知资源坐标（不重扫；探索过的区域才有记录） |
| `map_status` | all | 探索记忆统计（锚点数/覆盖范围/资源 Top10） |
| `move_to {x,y,z}` | op | 寻路移动 |
| `run_task {type,id,options}` | op | 运行时创建任务（8 种类型含 explore；options 过 schema 校验） |
| `stop_task {id}` | op | 停止并移除任务 |
| `find_block {blockName,maxDistance}` | op | 找地表暴露方块并走过去（maxDistance 16-256 限幅，防同步枚举冻结主线程） |
| `explore {maxDistance,direction}` | op | 单步探索：向方向游走（≤48 格）→ 采样记录资源与实体 → 报告；重复调用逐步推进；exclusive 任务运行中拒绝 |
| `follow_player {name\|off}` | op | 跟随/停止跟随 |

`!agent act status {}` 示例：`§astatus: {"state":"connected","reconnectCount":2,...}`

## 命令（!agent）

- `!agent chat <text>`：LLM 工具循环对话（**全员可用**；危险操作仍由技能层 op 门强制——C7/Y 修复后 buildSystem 的"普通玩家"分支转活跃；空文本入口拦截）
- `!agent act <name> [json]`：直调技能（op-only）
- `!agent doctor`：cloud/ollama 连通性诊断 + 生效模式/最近延迟（全员可用，只读，5s 短超时探测）
- `!agent reset`：清空调用者会话记忆
- 会话记忆：按玩家多轮上下文，LRU 上限 32 会话；冷却按玩家（一个玩家的请求不挡其他玩家）

## 上下文预算（A2）与 Ollama 端点（A1）

- **为什么改 native `/api/chat`**：Ollama 的 OpenAI 兼容端点（`/v1/chat/completions`）不处理 `options.num_ctx`——官方 wont-fix（ollama#2963/#6544），超窗**静默截断**（信息丢失不可控）。native `/api/chat` 才接受 `options.num_ctx`/`num_predict`。消息格式与 OpenAI 兼容同构（tool_calls 原样），仅 URL/options/响应解析变化。
- **预算裁剪**：每次请求前按 `window − maxTokens − 384` 预算（window = ollamaNumCtx；云端/测试无窗口不裁剪）。超预算按序裁剪：丢最旧纯文本历史轮 → 工具结果动态截短（下限 200）→ 当前用户消息截断。token 估算：CJK×1.0 + ASCII×0.25 + 其他×0.5（偏保守）。字符截断 ≠ token 截断的工程折中——宁可多裁，不让 Ollama 静默截断。
- `!agent doctor` 的最近延迟与 provider 模式配合预算观察（超窗时 prompt 被裁，可降 ollamaNumCtx 或减小 maxSteps）。

## 探索与空间记忆（B/C/D）

- **探索记忆**：DiscoveryMap（模块级单例 + `data/state.json` memory 键持久化）——已访问锚点（256 环形）+ 资源发现（chunk 去重、每块名 16 条、全局 512 条按 ts 淘汰）。无 explore 活动时 memory 为空，快照不膨胀。
- **explore 技能**（单步）vs **explore 任务**（后台螺旋）：技能 = LLM 驱动的按需探索（每轮 ≤5 步 × 48 格 ≈ 200 格）；任务 = 持续覆盖（方形螺旋 step 32，`!task new explore e1 {"maxDistance":128}`，exclusive 互斥，stopWhenDone 环满自然完成，scheduled 可配 durationMinutes）。
- 采样：23 种资源白名单 × findBlocks 64 半径 count 2（≈100ms/站，同步枚举防线：内部常量不走用户输入通道）；发现写入记忆，重要资源（钻石/绿宝石/远古残骸）经 webhook 推送（10 分钟/类型节流）。
- 环境感知数据源 26.1 备注：`bot.weather` 不存在（用 `bot.isRaining` + `bot.thunderState`）；实体 health/food 恒 undefined（只用 `bot.health`）；实体 `type` 可退化 'other'（`kind`/`entityType` 作标签）；玩家走 `bot.players`。

## 主动播报（summarize）

U6/U7：死亡与任务终态（completed/failed）时，若 L2 可用，经**单次无会话 LLM 调用**生成一句话播报（死亡死因、任务成果），失败/超时（10s）回退固定模板。全局 60s 冷却（模块级，跨重连保持）——低配 PC + Ollama 单请求队列下死亡播报与任务总结不会并发抢推理。播报永远是附加层：不阻塞重生/任务通知。

- 死亡 → `[bot] <LLM 一句话>`；任务终态 → `[任务 <id>] <LLM 一句话>`
- 技能层防线同款：`follow_player`/`find_block` 在 exclusive 任务运行中受仲裁器约束（拒绝/告警），`move_to` 坐标限世界边界 ±30000000

## 安全边界

- **密钥**：只从环境变量读取；fetch 失败日志不携带 key/body
- **工具滥用**：op 权限门 + maxSteps 上限 + cooldown + 参数校验；`run_task` 创建的任务同样受任务系统的区域/时长边界约束
- **回复长度**：≤250 字符，经 `sendChat` 分片
- **降级**：`auto` 模式下云端 4xx/网络错误自动回退 Ollama（一次）；Ollama 不可达时回复明确错误

## 历史记录：AgentProcess/JSONL IPC 方案（弃用）

早期设计（mindcraft 模式）：L1 主进程 ↔ agent 子进程 JSONL over stdin/stdout，协议 `{"type":"act"|"chat"|"result"|"event"}`。
弃用原因：单 bot 规模下 IPC 隔离无收益，进程内实现更简单可测；保留此段供未来多 bot/多 agent 场景参考。
